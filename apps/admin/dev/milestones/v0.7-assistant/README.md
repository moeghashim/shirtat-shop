## Brief and boundaries

Add `/dashboard/assistant`, titled **AI Assistant**, next to Chat in the existing sidebar. Keep standalone `/chat`, embedded `/dashboard/chat`, their person-to-person conversations and data source unchanged. Stream recorded or provider-generated OpenUI Lang through one renderer backed exclusively by tenboards components. Support Anthropic, OpenAI, xAI, Meta Muse Spark and Google, with server-only keys and env-overridable model defaults. Zero keys means useful recorded examples with no account, database, network provider or setup required.

The project's live demo and every `tenboards-preview` version remain recorded-only, without real provider keys. Adopters supply their own keys and, optionally, their existing database/auth configuration. No project-owned provider account, paid inference, Neon provisioning or production cutover is part of this milestone. Tests use synthetic keys and mocked streams, never live credentials.

Conversation state belongs to the mounted client view and clears on reload, sign-out/session loss or navigation away; no localStorage, cookie, URL transcript, conversation table or provider-managed conversation ID. No persistence table is justified. Provider requests contain only explicitly entered conversation text and the library instructions, never app records, session tokens, sample Chat history or account data.

Scope excludes RAG, tools/function calling, MCP, queries/mutations, browsing, uploads, images/audio, autonomous actions, CRUD, RBAC, billing, shared conversation history and new auth behavior. Generated forms and action buttons are deferred: v0.7's registry is read-only. Keep protected `src/components/ui/` and `src/components/calendar/` intact; compose at usage sites. Do not use OpenUI's pre-1.0 `react-ui` chat kit, its built-in component library, hosted Gateway or Autofix.

## Configuration matrix

“Keys” means nonblank server-side provider keys; whitespace-only values are absent. A nonblank invalid/revoked key enables its entry but yields a safe explicit provider error when used, never silent fallback. A model override alone enables nothing. The picker shows only configured providers; with one key it shows one selectable entry, with many it lists them in contract order. Each entry displays its effective model. Client requests select a provider ID, never an arbitrary model, key, base URL or headers; the server resolves the configured model again. No live model-discovery calls or free-text model selector.

| Runtime / deployment | Data/auth configuration | Zero keys | One or many keys |
| --- | --- | --- | --- |
| Node dev, no env | Demo data, auth off | Recorded stream; picker replaced by “Recorded demo” indicator | Enabled picker and live stream; open demo access remains open, with Origin and IP limits |
| Node dev or adopter Node server | DB, auth off | Recorded; app remains open | Same enabled picker, DB-backed IP limiter; no implicit auth enablement |
| Node dev or adopter Node server | DB + valid auth secret | Signed-in recorded access | Signed-in live access, user + IP limits; direct endpoint denies signed-out callers |
| Local workerd or adopter Worker | No DB, auth off (including forced `DATA_SOURCE=demo`) | Recorded; no DB connection | Runtime binding keys enable live requests; per-isolate IP limiter, limitations below |
| Local workerd or adopter Worker | DB via Hyperdrive or DATABASE_URL, auth off/on | Recorded; session required iff auth on | Binding keys enable providers, DB limiter; same session rule |
| Any runtime | Auth secret + no DB/forced demo, bad binding, unreachable required auth storage | Existing explicit configuration/service failure | Same failure; never downgrade to open recorded mode |
| Repo live demo | No DB/auth/provider secrets | Recorded only | Not provisioned; never set real keys here |
| PR preview / `tenboards-preview` | ASSETS only, no secrets/bindings except ASSETS | Recorded only | Reject contaminated preview inputs/inventory; never enable a provider |
| CI/tests | All valid/invalid mode combinations | Real recorded renderer | Synthetic sentinel keys + intercepted local provider streams; no paid egress |

`ASSISTANT_ORIGIN` is the proposed exact canonical origin for adopter live-provider deployments with auth off. Auth-on uses the existing validated `BETTER_AUTH_URL`; if both are set they must agree. Node/local workerd can use the actual loopback request origin. No-key recorded mode can compare Origin to the request URL's origin. Non-loopback live mode requires an explicit HTTPS canonical origin; reject missing, opaque `null`, malformed or cross-origin POST Origin, and do not trust forwarded Host/Origin values. This guards the new endpoint without changing auth's mode rule. Origin protection is CSRF mitigation, not authentication of an open demo client.

## Research record — official sources checked 2026-10-24

These are observations from official docs and published npm manifests on this date, not live-provider acceptance. Recheck account/model availability at implementation; do not silently move approved pins or substitute models.

### OpenUI 1.0

- The [MIT repository](https://github.com/thesysdev/openui) separates `react-lang` rendering from the headless/chat kit and framework-independent `lang-core`. [OpenUI's core loop](https://www.openui.com/docs/openui-lang/overview) is component definitions → generated instructions → incremental language parsing → rendering. It can run without a hosted service.
- [React API](https://www.openui.com/docs/api-reference/react-lang): `defineComponent` couples a name, Zod props and renderer; `createLibrary` enumerates allowed components. `Renderer` accepts `response`, `library`, `isStreaming` and error callbacks. Restricted action slots constrain prompting/schema only; they are not runtime authorization. Consequently this plan registers no actions or tool provider and validates every evaluated prop before passing explicit props into a wrapper.
- [System prompts](https://www.openui.com/docs/openui-lang/system-prompts): server-side `generateSystemPrompt({ library, promptOptions })` in `lang-core` uses a serializable library spec without importing React. Pin-matched package declarations were inspected: `Library.toSpec()` is the intended spec seam (verify exact exported types in 001). Generate/check the spec from the same registry, not a manually maintained second catalog. Disable toolCalls, bindings, builtinFunctions, editMode and inlineMode, supply no tools, and add recorded examples and untrusted-input rules. Prompt instructions alone are not a sandbox.
- [Language overview](https://www.openui.com/docs/openui-lang/overview): output consists of named assignments and component calls, e.g. `root = Stack([summary])`, rather than arbitrary JSX/HTML or JSON UI. Streaming may divide identifiers, strings or UTF-8 characters anywhere; the parser supports incomplete output. [Message protocol](https://www.openui.com/docs/openui-lang/message-protocol) uses `]]>openui:` markers for stored context; it is separate from transport framing. No stored-context protocol is needed here.
- [Server package](https://www.openui.com/docs/api-reference/server): `@openuidev/server` provides hosted Autofix and history helpers, including `/vercel` and `/openai` subpaths. Published `0.3.0` depends on lang-core and peers with LangChain; it is **evaluated and excluded**, not required for a local Start endpoint.
- [Telemetry](https://www.openui.com/docs/openui-lang/telemetry): install telemetry defaults on; runtime telemetry is opt-in. Installation/build/test guidance must disable it (`OPENUI_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1`), never enable runtime reporting, and verify no unrequested network calls or prompt capture. Do not activate bundled devtools/observability integrations.

## Streaming, registry and security contract

001 establishes a read-only root/stack, text, card, stats, badge, list, bounded table and simple bar/line chart registry using existing wrappers. Plain text is escaped React text. Chart data has finite numeric values and bounded series, labels and points; chart colors/layout are application enums with accessible tabular equivalents. No arbitrary CSS/className/style/DOM prop spreading, component names, event handlers or URL fields. No generated forms in v0.7. Links remain ordinary application-authored controls, outside generated output.

Both recorded and live paths emit the same versioned SSE envelope: text-delta with a string of OpenUI Lang, then exactly one finish or sanitized error. Use a POST fetch reader (not EventSource), incremental TextDecoder, byte accounting and cancellation. The client accumulates bounded language text into the same registry renderer. Only validated complete props/nodes render; partial invalid nodes remain placeholders. Server transport limits and client parser/node limits are independent. A stopped/truncated/invalid response is visibly incomplete; never interpret partial code as HTML or silently repair it via a hosted service.

Proposed fixed limits: request body **64 KiB** counted while reading, at most **20** user/assistant history messages, each user text at most **8 KiB UTF-8**, individual assistant history at most **32 KiB**, aggregate history within the request cap. Server-authored instructions are separate and bounded to **32 KiB**. Reject client system/developer/tool roles and unknown body fields. Output cap **64 KiB visible text** and **4,096 provider output tokens**, total deadline **60 seconds**, first content deadline **20 seconds**, inter-content idle deadline **15 seconds**; cap input reading at **10 seconds**. No automatic retries (`maxRetries: 0`); manual Regenerate is another charged/limited request. Parsing/render budgets: **200 nodes**, **12 levels**, **50 table rows × 8 columns**, **4 series × 50 chart points**. Apply byte limits to fixtures as well as providers; implementation tests establish these exact boundaries.

Rate limiting: **10 admissions / 60 seconds per authenticated user**, plus **30 / 60 seconds per trusted IP**; auth-off uses **10 / 60 seconds per trusted IP**. Count before upstream dispatch; no refunds after abort. DB source uses atomic conditional upsert on existing `auth_rate_limit`, namespaced `assistant:v1:` with time-window keys; hash identifiers, expire/prune old Assistant rows only, and never touch auth-owned keys. Guard consumption failure with 503; never fall back to memory after DB failure. Auth-off/no-DB uses a bounded TTL map (maximum 10,000 buckets, reject new buckets at capacity rather than evict active limits); no DB requirement is introduced for zero-config. This is per Node process/Worker isolate, resets on restart, and is **not a global spend quota**. Adopters with public paid, horizontally scaled no-DB deployments must enforce their own shared ingress/provider budget; adding distributed storage is outside this milestone. Tests must prove the stated local bound and DB cross-instance behavior, not claim global no-DB protection.

Trust `cf-connecting-ip` only on the actual Workers request path; never a caller forwarding chain. Node uses a verified server/proxy address when available, otherwise one conservative shared unknown bucket. Tests cover spoofed/missing IPs. Reuse `requireSession` for auth-on admission; user ID is server-derived, never supplied in the body. If dual limits partially consume, denial may consume the other bucket conservatively. Complete DB/session checks before streaming; do not retain a request-scoped DB client in the returned stream after `withRuntimeRequest` cleanup.
